# Changelog

## v0.2.5 — компактный пиксельный интерфейс со стеклом

- Согласованное оформление перенесено из эскиза в приложение: тёмная нейтральная основа, зелёный акцент, полупрозрачные поверхности и локальный Departure Mono с поддержкой кириллицы.
- Плитки аккаунтов 228×180 px содержат аватар, 2FA с таймером и копированием, последний запуск, число запусков, состояние Sandbox, подтверждения и доступ к сессии. Большая отдельная панель выбранного аккаунта убрана.
- Переход из плитки сразу открывает подтверждения нужного аккаунта. Изображения продаж и состав обменов сохранены.
- Медленно движущиеся фоновые частицы, плавное переключение режима и появление меню. В настройках доступны плотность стекла, яркость/отключение частиц и отключение анимации; выбор сохраняется локально.
- Частицы приостанавливаются в скрытом окне; настройки уменьшения движения в системе учитываются. Меню и подтверждающие диалоги больше не обрезаются стеклянными плитками. При ошибке загрузки аватара показывается инициал.

Проверки: [FLUENT-IMPLEMENTATION.md](docs/review-2026-09-19/FLUENT-IMPLEMENTATION.md).

## v0.2.4 — новый интерфейс и предметы в подтверждениях

- Спокойная тёмная тема с мятным акцентом, системный шрифт без внешних загрузок, читаемые формы и диалоги.
- Карточки или компактный список аккаунтов, поиск, панель Steam Guard и состояния сессии выбранного аккаунта. Дополнительные действия перенесены в меню с управлением с клавиатуры.
- Общая очередь подтверждений с фильтром по аккаунту. Для продаж отображается изображение предмета из Steam.
- Кнопка «Предметы» у обмена раскрывает «Вы отдаёте / Вы получаете»: изображения, названия, количество и SteamID участника. Данные загружаются по запросу и проверяются на соответствие текущему подтверждению.
- Недоступные изображения заменяются заглушкой; ошибка получения состава обмена не скрывает подтверждение. Ссылки на картинки ограничены публичными CDN Steam.
- Проверены русская и английская версии, окно 760×520, выбранные подтверждения, пустая очередь, ошибки сессии, недоступный состав и закрытое хранилище. Под блокировкой больше нет скрытых действий, доступных с клавиатуры.

Проверки и ограничения: [DESIGN-UPDATE.md](docs/review-2026-09-19/DESIGN-UPDATE.md).

## v0.2.3 — исправления после полного ревью

- Исправлены 23 пункта ревью: безопасный перенос workspace, проверка соответствия аккаунтов, транзакционная смена мастер-пароля и восстановление после сбоя записи.
- Привязка 2FA сохраняет выданные секреты до активации и завершённое состояние до показа успеха. Незавершённый мастер можно продолжить после перезапуска; повторы ограничены.
- Sandbox использует отдельные конфиги Steam; остановка процессов ограничена нужным экземпляром. Устранены коллизии имён песочниц.
- Backups хранят VDF и реестр в одной точке восстановления: до 10 точек, без повторных копий одинакового состояния и файлов `PATCHED`. Старая схема преобразуется автоматически.
- Исправлены обновление и копирование OTP, выбор в импорте, запуск игры через общие проверки, данные после смены workspace и восстановление повреждённых настроек.
- Окно можно растягивать. Добавлены управление диалогами с клавиатуры, подписи полей, сохранение языка, состояния автоматического входа и очистка backups в настройках.

Сценарии, проверки и ограничения: [FIXES.md](docs/review-2026-09-19/FIXES.md).

- Опциональное сохранение пароля после успешного входа через Windows DPAPI (текущий пользователь). Пароль хранится отдельно от `.maFile`, не экспортируется и удаляется через «Забыть сохранённый пароль» или вместе с аккаунтом/аутентификатором.
- После потери refresh token сессия восстанавливается сохранённым паролем и кодом из `.maFile`. Ручной вход также автоматически отправляет Steam Guard, если секрет уже доступен.
- Автовход проверяет соответствие SteamID, ограничивает число запросов и делает паузу между попытками. Неверный пароль/дополнительная проверка требуют ручного входа. Отмена входа не сохраняет пароль.
- Опрос входа больше не запускает параллельные запросы; поздний ответ после закрытия формы не продолжает флоу. Блокировка master vault во время запроса не создаёт незашифрованную копию `.maFile`.

- Исправлена ошибка SBIE1411: отсутствующие шаблоны, включая `Steam`, удаляются из секций `SteamShadow_*` при следующем запуске Sandbox. Новые ссылки добавляются только для установленных шаблонов.
- Выбор `Sandboxie.ini` соответствует порядку драйвера: пользовательский `IniPath`, каталог Sandboxie, Windows. `Sandboxie-Plus.ini` больше не принимается за конфиг песочниц.
- Обновление конфига сохраняет UTF-8/UTF-16, комментарии и пользовательские настройки; перед изменениями создаётся `Sandboxie.ini.steam-shadow.bak`. Ошибки чтения больше не заменяют конфиг пустым.
- Ручные и фоновые подтверждения используют общий механизм обновления access token и однократного повтора при `needauth`. Отсутствующий `SessionID` восстанавливается; временная сетевая ошибка больше не требует повторного входа.
- Автоподтверждение исходящих трейдов проверяет `is_our_offer` через Steam. `creator_id` — ID предложения, а не SteamID отправителя. При невозможности проверки автоподтверждение не выполняется.
- Отказ Steam не считается успешным подтверждением. Ошибки отображаются в разделе подтверждений; типы trade/market/phone/recovery/API key исправлены.


## v0.2.1 — Auto-updater

### Added

- **Проверка обновлений при старте.** Через ~4 с после запуска лаунчер тихо спрашивает GitHub Releases о последней версии. Если доступна новее — показывается модалка с release-notes и кнопками «Обновить» / «Позже».
- **Обновление в один клик.** По «Обновить» свежий `*-portable.exe` скачивается рядом с текущим, старый бинарь переименовывается в `*.old`, новый занимает его место, затем детач-скрипт (`%TEMP%\ssl-update-*.cmd`) ждёт завершения процесса, чистит `.old` и заново запускает лаунчер. Юзеру не надо ничего перетаскивать.
- Ссылка «На GitHub» в модалке — открывает страницу релиза.

### Notes

- Обновление работает только для портативной сборки (скачивает asset c именем, содержащим `portable` и заканчивающимся на `.exe`).
- Проверка best-effort: офлайн / rate-limit / отсутствие asset'а не ломают загрузку лаунчера.
- Никаких скрытых автообновлений без явного подтверждения.

## v0.2.0 — Steam Desktop Authenticator

Лаунчер теперь умеет работать со Steam Guard сам, без мобильного приложения.

### Added

- **Steam Guard TOTP** рядом с каждой карточкой аккаунта, который привязан к лаунчеру.
- **Импорт `.maFile`** из SDA / steamguard-cli. Поддерживается и plain, и encrypted (PBKDF2 + AES-CBC, SDA-совместимый формат).
- **Экспорт `.maFile`** обратно.
- **Мастер привязки нового Steam Guard** (13 фаз): login → diagnose (QueryStatus + PhoneStatus) → phone / email-Guard путь → activation → revocation-code → persist. Работает и для аккаунтов без привязанного телефона (email-Guard, `validate_sms_code=1` с активационным кодом из письма).
- **Список подтверждений** (trades / market / phone / login) с allow/reject и bulk-операциями.
- **Фоновый поллер подтверждений** с настраиваемым интервалом. Умеет авто-подтверждать только исходящие трейды (`creator_id == our steam_id`) и любые market-листинги.
- **Мастер-пароль** для всех `.maFile` в workspace — Argon2id (64 MiB, t=3, p=1) + AES-256-GCM. Ключ живёт только в памяти до `lock`.
- **Отвязка аутентификатора** через revocation-код прямо из UI.
- Вкладки `Accounts / Authenticator` в сайдбаре.
- RU/EN локализация всех новых строк.

### Changed

- Сайдбар перерисован: табы теперь стекаются вертикально с левой полосой-индикатором активной вкладки (pixel-шрифт не умещал два таба в grid 1fr/1fr).
- Destructive-confirm диалоги (remove account, remove authenticator, disable master password) — type-to-confirm с 600 мс grace и авто-фокусом на Cancel.
- Confirm-диалоги перекрывают обычные модалки (z-index 210 через `:has()`).

### Fixed

- `BeginAuthSessionViaCredentials/v1` теперь отправляет `input_json` вместо `input_protobuf_encoded` (Steam отклонял protobuf для web-login).
- `submit_code` корректно читает `x-eresult`-заголовок (Steam отвечает HTTP 200 даже на неверный Guard-код, настоящий статус только в header).
- Константы `EAuthSessionGuardType` приведены в соответствие со Steam (EmailCode=2, DeviceCode=3, DeviceConfirmation=4, EmailConfirmation=5, MachineToken=6).
- Email-Guard детектится через `allowed_confirmations` из login-шага (`QueryStatus` не различает «нет Guard» и «email Guard on» — оба возвращают `state=0`).
- `access_token` автоматически обновляется через `refresh_token` при HTTP 401 во всех authed-запросах модуля add (раньше recovery был только в `diagnose`).
- **Защита от потери ключей**: после `AddAuthenticator/v1` партиальный `.maFile` с `fully_enrolled=false` пишется на диск немедленно, до показа revocation-UI. Если окно закроется — секреты не потеряются.
- `FinalizeAddAuthenticator/v1` для email-Guard аккаунтов теперь требует `validate_sms_code=1` с кодом из письма (пробовать «без SMS» бесполезно, Steam всё равно отвергает).
- Поллер: per-login экспоненциальный backoff (15 → 300 с), полу-привязанные аккаунты (`fully_enrolled=false`) пропускаются.
- `diagnose` троттлится на 2 с — UI дёргает её по несколько раз подряд на каждый phase change.
- `LoginFlowModal`: поле Guard-кода сбрасывается при возврате в фазу `code` (Steam отверг старый код).
- TitleBar close prompts при активном wizard-е.
- Warning-checkbox при включении master-password («восстановить нельзя»).
- Status-body в логах `diagnose` обрезается до 200 символов.

### Security

- `shared_secret`, `identity_secret`, `refresh_token` не попадают в логи ни на одном этапе.
- `revocation_code` показывается в UI ровно один раз, после чего живёт только в `.maFile` на диске (в шифрованном виде, если мастер-пароль включён).
- Все секреты держатся в Rust-процессе и никогда не отправляются на JS-слой в plaintext, кроме revocation-кода на этапе «покажи юзеру один раз».

### Notes

- Clean-room реализация протокола Steam Mobile Authenticator. Код SDA и steamguard-cli (оба GPL-3.0) не копировался — использовались только публичные описания endpoint'ов.
